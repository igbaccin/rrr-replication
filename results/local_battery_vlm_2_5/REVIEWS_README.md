# Raw reviews and reproduction

This directory preserves the reported local-model battery: 941 writer-stage
attempts generated by vlm.2.4 (distribution `2.0.4+lm`) on 30 October 2026
from the same frozen ledgers as the July battery, and finished by the vlm.2.5
quotation verifier (distribution `2.0.5+lm`). The scores and exhibits built
from these reviews are under `results/corrected/`.

`reviews_raw/<batch>/<condition>/<run>.md` contains the 897 attempts that
produced a review: 889 successful reviews and 8 checker-flagged reviews, all
eight in the small-model ladder. The remaining 44 attempts ended in writer
failure and produced no review file. `per_run.csv` lists every attempt with
its model, outcome, E1 through E5 counts, citation and document counts, body
words, and the length of its closing section.

## The vlm.2.5 pass

vlm.2.5 differs from vlm.2.4 in one deterministic, text-local pass. The
quotation verifier reads quotations set in curly marks as well as straight
marks, leaves the quotations that the writer's own coverage sentences
introduce untouched, and removes a sentence whose quotation does not appear on
the page its citation names. The pass runs on the assembled review text and
needs the retained page text of the corpus.

Applied to the 897 vlm.2.4 reviews, the pass checked 88 quotations, skipped
1,178 coverage quotations, and removed one sentence from each of three
reviews; it changed nothing else. `materialization.json` records the three
changes with the hard-error counts before and after rescoring, and
`reviews_pre_materialization/<batch>/<condition>/<run>.md` holds the text of
those three reviews before the pass. `per_run.csv` records the outcome before
and after in `outcome_asrun` and `outcome`; two attempts move from
`checker_failed` to `success`.

Because the pass sits upstream of the redundancy walker and the style rewrite
in a live run, an end-to-end vlm.2.5 run could differ from the materialized
text in the paragraph of a removed sentence. The paper therefore reports the
profile as vlm.2.5 on the vlm.2.4 generation.

To reapply the pass, prepare a corpus work directory as described in
`docs/before_running.md` (the preprocessing step writes `data/page_text/`),
install the package from the repository root, and run:

```bash
python -m pip install .
python results/local_battery_vlm_2_5/reproduce_materialization.py --workdir <prepared corpus directory>
```

The script reports the reviews that the verifier changes and compares them
with `materialization.json`. Full E1 through E5 rescoring also needs the
corpus; most of its documents are copyrighted and must be obtained
separately.

## The running example

`run_records/phase_a_main/run_001/` deposits the complete record of the
run that the paper follows through its Methods section.
`source_run_2026-07-07/` holds the retrieval plan, admission record, topic
fit, outline plan, evidence ledger, narrative, run manifest and run metrics
of the source run; `writer_run_2026-10-30/` holds the writer call contracts,
every prompt and model response, the released review, its cited documents,
citation manifest, quality record, checker output, run manifest, run
metrics, replay provenance and status of the regenerated writer stage.
`inventory.json` lists the files and records the SHA-256 of the ledger from
which the writer stage started, which equals the ledger deposited in the
source-run folder.

## Redaction

One review, `runpod_20260709_031835/phase_g_qwen3_0_6b_refusal_wordsalad/run_007`,
copied an institutional download watermark from the page text of its source.
The deposited copy replaces that string with `[download watermark removed]`;
outcome labels, citations, and aggregate results are unchanged.
`summary.json` records the redaction. The same replacement is applied to the
retained passages of the running example's record, where the watermark
appears inside page text; `inventory.json` records those replacements.

## Denominators

`summary.json` and `conditions/*.json` count attempts that reached the writer.
The 1,184 attempts that refused or failed before the writer are preserved in
the analytical records under `results/corrected/analysis_source/`, and the
model table and figure there combine both groups over all 105 attempted runs
per ladder model.
